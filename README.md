# RefineTale

> 必要な機能だけを、今ある設計になじむ形で実装するためのCodexスキルです。

RefineTaleは、Codexにコードの追加・修正・リファクタリング・実装レビューを依頼するときに使うスキルです。

Codexはまず、「今回変えること」と「今までどおり保つこと」を分けます。そのうえで、既存コードや標準機能で解決できる部分は再利用し、実際に挙動が異なる部分だけを実装します。

目標は、コードをただ短くすることではありません。認証、入力の確認、データ保護、互換性、アクセシビリティなど、必要な安全性は維持します。一方で、「いつか使うかもしれない」という理由だけの設定、分岐、型、代替処理は増やしません。

## こんな悩みに向いています

- 大きめの機能を頼むと、依頼していない機能や設定まで実装されてしまう
- 同じ意味の状態や変数が増え、どれを使えばよいのか分かりにくくなる
- 既存機能と新機能で、ほぼ同じ処理が別々に作られてしまう
- 一時対応や将来対応のコードが、そのまま残り続けてしまう
- 実装は必要最小限にしたいが、認証・入力確認・互換性までは削ってほしくない

## RefineTaleを使うとどう変わるか

| Codexが確認すること | 実装への反映 |
| --- | --- |
| 今回の依頼 | 変える挙動と、今までどおり保つ挙動を分ける |
| 既存コード | 再利用できる実装、型、標準機能、導入済みの仕組みを探す |
| 状態やデータ | 同じ意味の値を重ねて持たず、管理する場所を一つにする |
| 処理の違い | 結果が本当に異なる場所だけで処理を分ける |
| 安全性 | 認証、入力確認、データ保護、互換性、アクセシビリティを維持する |
| 完成条件 | 依頼された内容と必要な確認を満たしたら、周辺機能を追加せず終了する |

Codexは次の順で進めます。

1. 依頼内容と既存コードを確認する
2. 変えることと、変えないことを分ける
3. 既存機能と新機能で同じ処理を見つける
4. 結果が異なる最小の場所だけを変更する
5. 依頼どおりの挙動と、維持する挙動の両方を確認する

## インストール

Codexに次のように依頼して、GitHubリポジトリからRefineTaleをインストールします。

```text
$skill-installer install https://github.com/alka0000-dev/codex-skill-refinetale
```

インストール後にスキルが表示されない場合は、Codexを再起動します。

## 使い方

コード作業の依頼の先頭に`$refinetale`を付けます。

```text
$refinetale この機能を、既存の挙動を維持しながら実装してください。
```

過剰実装がないか確認するレビューにも使えます。

```text
$refinetale この差分に、不要な分岐、重複した状態、先行実装がないかレビューしてください。
```

実装方法を細かく指定しなくても、RefineTaleが既存コードと依頼内容を確認します。使ってほしい方式や完成形が決まっている場合は、その希望も一緒に伝えてください。

### 依頼に含めると分かりやすいこと

次の3点が分かると、Codexが変更範囲を判断しやすくなります。

- 何を変えたいか
- 何を今までどおり保ちたいか
- どの状態になれば完成か

すべて決まっていなくても構いません。分かる範囲で、たとえば次のように伝えられます。

```text
$refinetale
変更したいこと: （追加・修正したい挙動）
保ちたいこと: （変えたくない既存の挙動）
完成条件: （確認できれば完了と判断できること）
```

### 完了時の報告

RefineTaleでは、コード変更・具体的な実装案・実装レビューの最終回答で、依頼時に明示された変更内容と、今までどおり保つ挙動を、それぞれの検証結果と対応づけて示すようCodexに求めます。

- 今回変えると定めた挙動
- 今までどおり保つと定めた挙動
- 各挙動を確認した方法と結果
- 確認を実行できなかった場合は、未実施の理由、必要な最小テストと期待結果

必要な証拠が揃っていない場合は、完了したとは報告しません。

## 比較評価で確認した効果

2026-09-02に、一つの公開リポジトリの同じバージョンへ、6種類のフロントエンド機能を追加する比較評価を行いました。各機能をRefineTaleなし・ありで3回ずつ、合計36回実装しています。

この評価では、どちらの条件も全18回でビルドと完成条件を満たしました。そのうえで、RefineTaleを使った条件では、追加された実装コードの合計が56.9%減りました。

```text
追加された実装コード（合計）

RefineTaleなし  ████████████████████  4,118行
RefineTaleあり  █████████               1,777行
```

| 確認項目 | RefineTaleなし | RefineTaleあり |
| --- | ---: | ---: |
| ビルド・完成条件を満たした実装 | 18/18 | 18/18 |
| 追加された実装コード | 4,118行 | 1,777行 |
| 完成度・設計との一貫性・実装範囲などの匿名採点 | 87.5% | 98.6% |
| 重大な失敗 | 0件 | 0件 |

特に、日付選択、ファイル選択、複数ステップのフォームでは、依頼されていないAPI、独自の状態管理、追加画面などを抑える差が確認できました。

一方で、RefineTaleを使った実行は、平均実行時間が26.9%、生成した回答のトークン数が31.1%増えました。短い回答や速い実行を得るためのスキルではなく、変更後に保守するコードや、覚えておく必要がある実装上の決まりを減らすためのスキルです。

この結果を利用判断に使う際は、次の範囲に注意してください。

- 対象は、一つの公開リポジトリに追加した6種類のフロントエンド機能です
- 同じモデルと推論強度で比較した、作者側による評価です
- ビルドと課題ごとの完成条件は確認しましたが、ブラウザ操作、見た目、自動E2Eテストは評価していません
- すべての言語、リポジトリ、機能で同じ効果を保証するものではありません

## 向いていない依頼

RefineTaleは、次の依頼には使用しません。

- 一般的な技術説明や質問への回答
- コードを扱わない文章作成
- 脆弱性を見つけること自体が目的のセキュリティ監査

セキュリティに関係する通常の機能追加や修正では、認証などの安全上必要な境界を維持するために利用できます。
